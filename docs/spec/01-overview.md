# UMPA - 概要・基本概念

## アーキテクチャ概要

### 設計哲学

UMPA（汎用多言語プラグイン・メタアーキテクチャ）は、**任意の Claude Code プラグインを複数言語でスケールさせる**ためのメタアーキテクチャです。

**コアコンセプト**: 関心の分離（Separation of Concerns）

```
実行層（English, Claude向け）
├── skills/        → スキル（プロセス定義）
├── commands/      → スラッシュコマンド
└── agents/        → カスタムエージェント
    ↓
学習層（多言語、人間向け）
├── references/ja/
├── references/en/
└── references/xx/ (任意の言語)
    ↓
設定層
├── plugin.json    → プラグインメタデータ
└── .mcp.json      → MCP統合（オプション）
```

---

## 3層構造の特徴

### 1. 実行層（Execution Layer）

- **対象**: Claude Code エンジン
- **言語**: 英語のみ
- **内容**: スキル、コマンド、エージェントの定義
- **変更頻度**: 機能追加時のみ

**例**:
```
skills/lean-canvas/SKILL.md
├── スキル名
├── 説明
├── プロセス（英語）
├── 入出力形式
└── ベストプラクティス
```

### 2. 学習層（Learning Layer）

- **対象**: ユーザー（人間）
- **言語**: 複数言語対応可（ja, en, zh-CN, etc.）
- **内容**: 背景知識、実装ガイド、ケーススタディ、応用テクニック
- **コンテキスト負荷**: **ゼロ** (Claude Code は読み込まない)

**例**:
```
references/ja/
├── README.md          → 学習ガイド
├── 01-concept.md      → 背景・理論
├── 02-step-by-step.md → 実装ガイド
├── 03-case-studies.md → 実例
└── 04-advanced.md     → 応用テクニック

references/en/
└── (同じ構成)

references/zh-CN/
└── (同じ構成)
```

### 3. 設定層（Configuration Layer）

- **対象**: プラグインシステム
- **内容**: メタデータ、外部統合設定
- **変更頻度**: バージョン更新時のみ

## メリット

### ✅ スキルは英語で1回書くだけ

実行層（SKILL.md など）は英語で書き、複数言語対応は学習層で実現。

```
スキルを1回書く → 自動的に20言語対応可能
```

### ✅ 言語追加時にコンテキストが増えない

references/ フォルダは Claude Code に読み込まれないため：

```
初期コンテキスト: ~1,200トークン（固定）
言語追加後: ~1,200トークン（変わらず！）
```

### ✅ 言語追加がシンプル

新言語対応：

```bash
./tools/add-language.sh zh-CN  # フォルダ作成
翻訳ファイルを編集
git commit & push
```

コード変更ゼロ。フォルダ追加だけ。

### ✅ スケーラビリティ

| スケール | 1つのプラグイン | 複数プラグイン |
|---------|-------------|----------|
| スキル数 | 1 → 100+ | 複数プラグイン対応 |
| 言語数 | 1 → 20+ | 各プラグインで独立 |
| コンテキスト | 固定 | 固定 |

## 適用可能なユースケース

UMPA は以下のすべてのケースに対応：

✅ **ビジネステンプレート**  
Lean Canvas、ペルソナ、価値提案など

✅ **コード生成**  
React コンポーネント、Python スクリプトなど

✅ **ライティング支援**  
ブログ記事、マーケティングコピーなど

✅ **データ分析**  
チャート、レポート、可視化など

✅ **プロジェクト管理**  
タイムライン、ロードマップ、チェックリストなど

✅ **学習・教育**  
コース、チュートリアル、演習など

✅ **技術ドキュメント**  
API ドキュメント、セットアップガイドなど

✅ **その他**  
多言語対応が必要な **あらゆるタスク**

## 設計原則

### 関心の分離

実行層と学習層を完全に分離：

- **実行層**: 「プロセス」に集中（WHAT & HOW）
- **学習層**: 「背景」と「理解」に集中（WHY）

**結果**:
```
スキル開発者 → 実行層だけに集中
翻訳者 → 学習層だけに集中
ユーザー → 学習層で理解を深める
```

### プログレッシブ・ディスクロージャー

徐々に詳しくなる構成：

```
SKILL.md
  ↓ （詳しく知りたい場合）
references/01-concept.md
  ↓ （実装方法を知りたい場合）
references/02-step-by-step.md
  ↓ （実例を知りたい場合）
references/03-case-studies.md
  ↓ （応用を知りたい場合）
references/04-advanced.md
```

---

## スケーラビリティマトリックス

| 次元 | 最小 | 推奨 | 最大 | 努力 |
|-----|------|------|------|------|
| **スキル数** | 1 | 5 | 50+ | 線形 |
| **言語数** | 2 | 5 | 20+ | 線形（フォルダ追加のみ） |
| **初期コンテキスト** | ~1,200t | ~1,200t | ~1,500t | 固定 |
| **言語追加の時間** | 2h | 4-6h | 8h | 線形 |

**重要**: スキルを追加してもコンテキストはほぼ変わりません。言語を追加してもコンテキストは増えません。

## 実装例

### Lean Canvas プラグイン

```
実行層:
  - skills/lean-canvas-generator/SKILL.md

学習層:
  - references/ja/01-concept.md
  - references/ja/02-step-by-step.md
  - references/ja/03-case-studies.md
  - references/ja/04-advanced.md
  - references/en/ (同じ構成)

設定層:
  - .claude-plugin/plugin.json
```

**特徴**:
- スキルは1つ（Lean Canvas 生成）
- 日本語と英語の学習資料あり
- 言語追加は `add-language.sh` だけ
