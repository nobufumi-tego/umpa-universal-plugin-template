# Lean Canvas 実装ガイド

## 準備

### 必要なもの
- 紙またはホワイトボード
- チームメンバー（1人でもOK）
- 顧客インタビューの情報（できれば）

### 予想時間
初回作成: 2-3時間
改善: 30-60分

## プロセス

### ステップ 1: 問題を定義

顧客が実感している課題を、最大3つ定義します。

#### ポイント
- 推測ではなく、顧客インタビューから得た情報を使用
- ビジネスニーズではなく、顧客ニーズを中心に

#### NG例
❌ 「多くの人が困ると思う問題」
❌ 「我々が解決したい問題」

#### OK例
✅ 「実際に顧客から聞いた具体的な課題」
✅ 「顧客が月に複数回直面する問題」

### ステップ 2: 顧客セグメントを定義

問題を実感している顧客層を具体的に描写します。

**テンプレート**:
```
[職業]: [具体的な行動や特徴]
例: フリーランス: 複数プロジェクトを同時進行している
```

### ステップ 3: 解決策を定義

最小限の機能で問題を解決する方法を記述します。

**重要**: すべての機能を入れない。最小限（MVP）で。

### ステップ 4: 独自の価値提案を作成

競合と異なる理由を1文で説明します。

**テンプレート**: 「[対象] にとって、[解決策] により [メリット] を実現する」

### ステップ 5: チャネルを決定

顧客に製品・サービスを届ける方法：
- ウェブ、モバイルアプリ
- SNS、口コミ
- 営業チーム、パートナーシップ

### ステップ 6: 収益モデルを定義

どのようにお金を稼ぐか：
- サブスクリプション
- 1回売切
- フリーミアムモデル
- B2Bライセンス

### ステップ 7: コスト構造を列挙

主な費用項目（初期、月次）：
- 人件費、サーバー、マーケティング

### ステップ 8: 主要メトリクスを設定

成功を測る指標：
- MAU（月間アクティブユーザー）
- 顧客獲得コスト（CAC）
- LTV（顧客生涯価値）

### ステップ 9: 圧倒的な利点を確認

競合が真似できない理由：
- 創業者の専門知識
- データやアルゴリズム
- ネットワークやパートナーシップ

## よくある間違い

### 間違い 1: 問題が曖昧

**何が起こるか**: ビジネスの方向性がぶれる

**対策**: 実際に5人以上の顧客にインタビューし、共通課題を抽出

### 間違い 2: ターゲットが広すぎる

**何が起こるか**: マーケティングメッセージが曖昧になる

**対策**: 具体的な1つのセグメントに絞る

### 間違い 3: 機能を詰め込みすぎ

**何が起こるか**: 実装が遅れ、最初のローンチができない

**対策**: MVP（最小限の製品）を定義する

## チェックリスト

- [ ] 問題が顧客から聞いた実際の課題か
- [ ] ターゲット顧客が明確に描写されているか
- [ ] 解決策が最小限か（機能が多すぎないか）
- [ ] 競合との差別化が明確か
- [ ] 収益モデルが現実的か
- [ ] チームが全要素に同意しているか
